noBS CAD **0.2.2** is a compatibility and reliability follow-up to
[0.2.1](https://github.com/jackControls/noBS-CAD/releases/tag/v0.2.1). It makes
the portable Linux build usable across the supported Ubuntu baseline, improves
file interchange, and fixes several modeling and interface defects.

> **Pre-alpha.** Keep backups of work you care about.

## What changed since 0.2.1

**Linux packaging** — the AppImage is now built on Ubuntu 22.04 with a glibc 2.35
ceiling, carries a world-executable launcher and its required Wayland server
runtime, and uses the host graphics-client ABI so newer Mesa drivers can load.
Release CI audits permissions and glibc symbols, then launches the same artifact
on Ubuntu 22.04 and 26.04. These changes address the AppImageHub catalog failure
reported in [AppImage/appimage.github.io#6426](https://github.com/AppImage/appimage.github.io/pull/6426)
(#176).

**File interchange** — STEP files can be opened directly through **File → Open**
(#169). 3MF export now writes a standard model package instead of a slicer-project
stub, so Bambu Studio, OrcaSlicer, Cura and PrusaSlicer recognize the exported
geometry consistently (#166).

**Modeling and interface** — hole placement uses the picked sketch point on the
support face (#173), and paired form fields remain bottom-aligned when one label
wraps (#175).

**Reliability and release engineering** — MCP inbox stress tests share one bounded
budget and recover cleanly after a poisoned environment lock (#170); the desktop
lockfile includes the print package (#174); pushed release tags now publish the
artifacts built by that exact run, with version and release-note guards before
any release is made public (#168).

**Documentation** — the README now leads with the finished product experience,
uses the rendered showcase media, and keeps repository navigation under
`docs/` (#172).

## Project compatibility

The `.nbcad` container version remains 1 and the model schema remains 9. Version
0.2.2 opens projects written by 0.2.1 and earlier; projects saved by 0.2.2 do not
introduce a new schema revision.
